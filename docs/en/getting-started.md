# Getting started with in:si

in:si is a local learning environment. Course texts, assignments, projects and
progress remain understandable files on the selected device or storage medium.
Normal learning workflows need neither an account nor permanent connectivity
after setup.

## Select a course

The start screen lists installed courses. A course can be created locally,
imported as a portable ZIP or installed from a deliberately selected
repository. Published material and personal workspaces remain separate so that
a course update cannot overwrite learner work.

## Learn and practise

**Script** contains the course chapters. Explicitly marked examples can be
copied or run when the sandbox is ready. Opening a chapter never executes an
ordinary code block automatically.

**Assignments** combines instructions, staged hints, an editor and trainer
feedback. Saving and running are separate actions. Progress is stored locally
inside the course workspace.

## Build projects

**My projects** stores longer programs, documentation and optional Pyxel
resources as ordinary files. Before execution, in:si creates a limited local
snapshot when the project has changed. Learners can also save named states with
a short comment. The timeline validates and restores older states after first
saving the current working state.

## Integrated execution and external IDEs

Integrated execution is enabled only after the operating-system sandbox passes
a real self-test. in:si does not silently fall back to an unrestricted process.

**Open in IDE** deliberately leaves the in:si sandbox and starts Thonny,
VS Code or another configured IDE with the normal permissions of the user
account.
